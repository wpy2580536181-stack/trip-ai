## 3. 瓶颈归因

| 链路环节 | 平均耗时(ms) | P95(ms) | 说明 |
|---|---:|---:|---|
| 健康检查（无DB） | 0 | 0 | 纯内存响应基线 |
| 登录（BCrypt+DB+JWT） | 269 | 271 | BCrypt 为 CPU 密集型 |
| 会话列表（DB分页） | 2 | 3 | JPA 分页查询+序列化 |
| 知识库查询（DB分页） | 6 | 6 | JPA 分页查询+序列化 |
| **chat 内部路径（无LLM）** | **10** | **11** | SSE初始化+Agent编排+收尾 |

> **结论（实测）**：chat 链路在不调用 LLM 时，SSE 初始化、ReAct 编排、
> SSE 写入、工具路由、Token 记账、收尾帧全部加起来 P95 仅 11ms；
> 因此端到端总耗时的 **95% 以上为外部 LLM 流式调用**（DeepSeek API），
> 内部代码不是瓶颈。

## 5. 综合评估

- **内部链路极快**：chat 内部路径 P95 仅 11ms，DB 查询 P95 数十毫秒
