# Structured Cards — 对话内结构化卡片渲染

本技能确保用户提问时触发对应的工具调用，系统会**自动将工具结果渲染为可视化卡片**嵌入对话流。

## 卡片类型与触发规则

### 1. POI 列表卡片（附近美食/景点）
当用户询问某个位置周围的餐饮、景点、休闲场所时：

1. 如果用户没给坐标，先调用 `search_commute_tips_tool(keywords=地名, city=城市)` 获取坐标
2. 调用 `search_nearby_commute_pois_tool(lat, lng, keywords=分类词, limit=10)`
   - 问吃的 → `keywords="餐饮"` 或 `"美食"`
   - 问景点 → `keywords="景点"` 或 `"文化"`
   - 问咖啡/休息 → `keywords="咖啡馆"` 或 `"公园"`
   - 通用 → 不传 keywords，让 API 返回综合结果
3. 系统会自动将结果格式化为 POI 列表卡片（排名 + 名称 + 评分 + 距离 + 人均）

### 2. 通勤对比卡片（路线方案）
当用户询问两地之间的出行方案时：

1. 如果起终点只有名称没坐标，先调用 `search_commute_tips_tool` 获取坐标
2. 调用 `compute_optimal_commute_tool(origin, destinations, mode, city, compare_modes)`
   - 用户没指定出行方式时设 `compare_modes=true` 横向对比
3. 系统自动渲染通勤对比卡片（步行/公交/驾车/骑行，耗时 + 距离，推荐方案高亮）

### 3. 行程修改 Diff 卡片
当用户要求修改行程中的某部分时，系统会自动生成修改方案并通过 Diff 卡片展示变更内容，用户可「采纳」或「放弃」。见 trigger_modify / trigger_patch 工具。

## 关键原则

- 工具调用在前，LLM 自然语言输出在后。先让工具返回真实数据，再基于数据组织回答
- 系统会自动处理卡片渲染，LLM 不需要手动格式化卡片内容
- 工具返回的数据已经包含卡片所需的所有信息，LLM 的文本回答可以简洁
- 卡片与文本互补：卡片展示结构化数据，文本提供额外说明和建议

## 已知限制

- POI 工具依赖高德 API，部分偏远地区可能返回空结果，此时降级用知识库或通用知识
- 通勤工具依赖真实路网，步行/骑行方案在城市间长距离场景不适用
